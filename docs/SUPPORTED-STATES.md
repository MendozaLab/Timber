# Supported state and claim limits

Version 0.1 targets macOS and Linux with a local filesystem. Windows is unsupported. The implementation refuses unsupported capture states rather than silently degrading a complete-recovery claim.

| State | Initial behavior |
|---|---|
| Regular files and directories, including empty directories | Capture paths and bytes; restore the documented permission bits. |
| Symbolic links | Preserve link targets without following them during capture or restoration. |
| Executable bits | Preserve and compare. |
| Staged contents different from working contents | Capture both versions; preview selects one layer. |
| Tracked deletions | Preserve their absence and logical index state. |
| Untracked files | Capture; integration requires explicit extra-file selection. |
| Ignored files | `inspect` summarizes them by default (count, total bytes, and the 20 top-level paths with the most entries); `inspect --list-ignored` lists every path. Capture only explicitly selected paths; report omissions. |
| SHA-1 Git repositories | Supported; other Git object formats are refused in version one. |
| Detached commit | Capture the commit identity and reconstruct independently with detached HEAD; original branch name is recorded only. |
| Preservation folder with or without a receipt | Capture current supported files; historical completeness remains unknown. |
| External Git dependency declared by a folder | Inspection checks pinned identities and, when requested, saved layer fingerprints. Explicit `import --dependency-repo` preserves supported commit/stash object closures for independent `restore-git`. |
| Missing registered worktree | Report the missing location; do not prune or repair it. |
| Many registered worktrees | List all registrations, deeply inspect the requested worktree by default; `--worktree` and `--all-worktrees` opt into wider scans. |
| Recovery-folder comparison | Explicit `--compare-folders` reports same-path matches, competing versions, proposed additions and exact saved-copy overlaps without modifying originals. |
| Unsupported or changing inspection input | Retain partial findings and exact blockers; do not imply that unknown paths were clean or redundant. |
| Unresolved merge, rebase, cherry-pick, or similar operation | Refuse a worktree checkpoint. |
| Submodules (gitlinks, index mode 160000) | Record the pointer, never the contents. `checkpoint` records each gitlink path as a manifest entry of kind `submodule`, with the gitlink commit id from the index and, when the submodule is initialized, the commit id its HEAD resolves to; an empty, uninitialized submodule directory records the index id alone. The submodule's files are never read or captured. `restore` recreates the path as an empty directory with the gitlink in the restored index, and never fetches or initializes a submodule; `verify` and `restore` print each recorded submodule with both ids under `submodules_recorded_not_captured`. Plans compare two gitlinks at the same path by commit id only; a preview stops as a conflict, naming the path, when both sides moved the pointer to different commits. `inspect` reports submodules as `submodules_recorded_not_captured`, not as a blocker. Refuse, naming the path, a gitlink whose path is missing, is not a real directory, holds files without a `.git`, or whose HEAD cannot be read. |
| Nested repositories | Refuse capture; handle them separately. `inspect` lists every directory below the worktree, other than a submodule at a gitlink path, that holds its own `.git` directory or file under that worktree's blockers, with its relative path, whether it is tracked, untracked or ignored, a count, and the message "checkpoint will refuse this worktree until nested repositories are handled". Inspection does not read a nested repository's contents. Linked worktrees of this same repository are not counted here; see the next row. |
| Linked worktrees inside a worktree | Skip them; capture each one on its own. A nested `.git` is a linked worktree of this repository only when it is a regular file of at most 4096 bytes holding exactly one line `gitdir: <path>`, that path reaches `<common dir>/worktrees/<name>` without passing through any symbolic link, and Git's own registration file in that directory names this same `.git` file back. Anything else, including an unreadable, malformed or oversized `.git` file, a pointer into another repository, a copied pointer, or a pointer through a symbolic link, is a foreign nested repository and keeps the refusal. `inspect` lists linked worktrees under `linked_worktrees_inside` (path, registration name, tracking) and not in the nested-repositories blocker. `checkpoint` skips each such folder without reading it and records it in the manifest with reason `linked_worktree_captured_separately`; `verify` and `restore` list those paths under `linked_worktrees_captured_separately`, nothing below them is restored, and `assess` prunes them like operator exclusions. `--exclude` naming a linked worktree folder is still accepted and recorded as `excluded_by_operator`. Refuse, naming the folder, a linked worktree whose folder holds a tracked path of the outer worktree (it stays in the blocker), and an `--exclude` path strictly inside a linked worktree. |
| Slow Git operations | Each single Git operation runs under a limit of 120 seconds by default; the global `--git-timeout <seconds>` (1 to 86400) changes it for one run, and a repository's `timber.toml` `git_timeout_seconds` changes it for `inspect` and `checkpoint` when the flag is absent. A timeout stops that operation, leaves the source untouched, and leaves the result partial or the capture refused, with the operation and the limit named. |
| Operator exclusions (`checkpoint --exclude PATH`) | Skip each named path and everything below it for this run only, and record it in the manifest as `excluded_by_operator`; `verify` and `restore` list those paths. An excluded untracked or ignored folder that contains a nested repository no longer triggers the refusal. Refuse, naming the path, an exclusion that matches nothing, overlaps another exclusion or an `--include-ignored` selection, passes through a symbolic link, or covers any tracked path (with staged or working changes, or clean). Exclusions are never remembered, never inferred, and never decide that anything is disposable. |
| Team convention file (`timber.toml` at the repository root) | `timber init` writes a commented template and refuses to overwrite an existing file or follow a symbolic link. `inspect` and `checkpoint` print the file they read, or that none was found, and report it under `convention`. `store` applies to `checkpoint` when `--store` is absent (before `TIMBER_STORE`); `git_timeout_seconds` applies when `--git-timeout` is absent; `exclude` applies to every `checkpoint` as if passed with `--exclude`, under the same refusals (including the refusal of a path strictly inside a linked worktree), and is recorded as `excluded_by_convention_file`; `assess` prunes it like operator exclusions and linked worktrees. `--exclude` adds to the list and overrides an entry it equals or contains; `--include-ignored` overrides an entry it overlaps; an `--exclude` strictly inside an entry is refused. `schedule` is free text; nothing is ever scheduled. Refuse, naming the key or line, an unknown key, a table, a repeated key, a wrong value type, an unset environment variable in `store`, or a relative `store`. |
| Sparse, shallow, or partial repository; missing objects | Refuse worktree capture; do not fetch data. |
| Unsupported index flags or stages | Refuse rather than manufacture equivalent index state. |
| Cloud placeholders | Refuse content capture without triggering hydration. |
| Special files, including sockets, devices, and pipes | Refuse capture. |
| Non-UTF-8 filenames or filesystem collisions | Refuse with the affected path. |
| Custom or union merge driver | Refuse preview semantics that the isolated engine does not support. |
| Existing restoration or preview directory | Refuse overwrite. |

## Inspect output schema

`inspect` results carry `"schema": 2` inside the command result. In schema 2, each scanned worktree's `ignored` field is a bounded summary object, `{"count", "bytes", "top_dirs": [{"path", "count", "bytes"}]}`, with at most 20 top-level paths ordered by entry count, then path; with `--list-ignored` it is the complete per-path list, and `scope.list_ignored` is `true`. Staged, working and untracked lists are complete in both modes. Schema 1 results always carried the full list. Each scanned worktree also carries `submodules_recorded_not_captured`, a list of `{"path", "gitlink_commit", "checked_out_commit"}` (empty when there are none); this field is additive and does not change the schema number. Compatibility: consumers detect the shape by the schema number (and, for schema 2, `scope.list_ignored`), never by guessing. Stored manifests, plans and receipts keep their own schema 1; the command envelope's `schema` is also unchanged. Since 0.2.0 the envelope also carries an additive `generator` object (`name`, `version`, `url`) identifying the Timber build that produced it.

The recovery guarantee concerns the supported captured paths, contents, symlink targets, executable bits, logical staged index (including submodule pointers), and recorded base commit. It never covers a submodule's contents. It does not preserve running processes, application state, credentials held in memory, open database transactions, ownership, access-control lists, arbitrary extended attributes, resource forks, hardlink topology, or every filesystem timestamp.

A content hash establishes byte identity. It does not establish truth, ownership, usefulness, completeness of a former worktree, or approval to delete another copy.

A verified local checkpoint is not automatically an independent backup. Independent backup remains unassessed unless separately verified outside this tool's initial contract.
