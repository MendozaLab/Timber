## 0.1.1 (2026-10-28)

- `timber gc --dry-run` lists every incomplete capture marker (id, age, journaled objects and bytes) and every object no completed checkpoint references, with the bytes `timber gc` would reclaim; it writes nothing. `timber gc` checks that every completed checkpoint's objects are present (refusing before any deletion, naming the checkpoint, if one is missing), then removes the incomplete markers, unreferenced objects and leftover temporary items, and prints what it removed and kept, with bytes. It takes no source path, never removes completed checkpoints, and refuses while a capture runs in the same store. Each capture now journals in its incomplete marker the objects it added, and a refused capture names its marker, the bytes it holds and `timber gc --dry-run`; markers from earlier versions are reported as `journal absent`. (2026-10-28)
- Team convention file: a committed `timber.toml` at the repository root may set `store`, `exclude`, `git_timeout_seconds` and `schedule` (a note; nothing is ever scheduled). `timber init` writes a commented template and refuses to overwrite. File exclusions apply to every `checkpoint` as if passed with `--exclude` and are recorded as `excluded_by_convention_file`; `verify` and `restore` list them as `excluded_by_convention_file`. Command-line `--store`, `--git-timeout`, `--exclude` and `--include-ignored` add to or override the file. `inspect` and `checkpoint` print which convention file they read, or that none was found, and report it under `convention`. Unknown keys are refused, naming the key. (2026-10-28)
- `checkpoint` captures worktrees that contain submodules: each gitlink is recorded as a manifest entry of kind `submodule` with the commit id in the index and, when initialized, the commit its checkout points at; the submodule's files are never captured. `restore` recreates the path as an empty directory without fetching or initializing it, `verify` prints both ids, plans compare the pointers by commit id, a preview stops as a conflict naming the path when both sides moved the pointer, and `inspect` reports `submodules_recorded_not_captured` instead of a blocker. A submodule whose path is missing, holds files without a `.git`, or whose HEAD cannot be read is still refused, naming the path. (2026-10-27)
- Global `--git-timeout <seconds>` (default 120) sets the limit for each single Git operation; a timeout leaves the source untouched and the result partial, and the message names the operation and the limit that applied. (2026-10-27)
- `checkpoint --exclude <path>` (repeatable, relative to the worktree, per run only) skips a disposable untracked or ignored path and records it in the manifest as `excluded_by_operator`; `verify` and `restore` list the exclusions. Refused, naming the path, for tracked paths, overlapping or unmatched paths, and paths that overlap an `--include-ignored` selection. (2026-10-27)
- Linked worktrees of the same repository inside a worktree (a `.git` file whose `gitdir:` resolves, without symbolic links, to `<common dir>/worktrees/<name>`, with Git's registration pointing back) are no longer nested-repository blockers: `inspect` lists them under `linked_worktrees_inside`, `checkpoint` skips each one without `--exclude` and records it with reason `linked_worktree_captured_separately`, `verify` and `restore` print them under `linked_worktrees_captured_separately`, and `assess` prunes them. Foreign nested repositories, and any `.git` file that is unreadable, malformed or points elsewhere, keep the refusal. (2026-10-27)
- `inspect` lists nested repositories below a worktree as a blocker with their tracking state and the message "checkpoint will refuse this worktree until nested repositories are handled". (2026-10-27)
- The store privacy refusal names the remedy: `chmod 700`, or let Timber create the store path. (2026-10-27)
- Documentation: field learnings, three proposals (bounded output, nested repositories, submodules), an agent operator guide, notes on per-file untracked counts, viewers that refuse file URLs, and rendering partial results. (2026-10-27)

## 0.1.0 (2026-10-26)

- First public version: read-only `inspect`, `checkpoint` with staged and working layers captured separately, `verify` by independent restore, `plan`, `preview` in a separate repository, `assess` for source drift, `report` to self-contained HTML, `import` and `restore-git` for folders that depend on another repository's Git data.
